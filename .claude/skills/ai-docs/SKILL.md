# AI Docs 루틴

기술문서를 최신 상태로 유지한다. **두 개의 모드**가 있고, 호출될 때 어느 쪽인지 판단한다.

- **일간 — 판정 모드** (`--scan`): 뉴스를 보고 대기열에만 쌓는다. 문서를 고치지 않는다.
- **주간 — 반영 모드** (`--apply`): 대기열에서 골라 실제로 쓰고 배포한다.

인자가 없으면 대기열 상태를 보고 판단한다. 오늘 이미 판정했으면 반영 모드로 간다.

## 실행 위치

이 저장소의 루트에서 작업한다. 집 PC 와 클라우드(Claude Code routines) 양쪽에서 돈다.

- 집 PC: `/home/sj/src/study/ai-daily`
- 클라우드: 저장소가 체크아웃된 위치 (경로가 다르므로 가정하지 않는다)

**클라우드에서 처음 돌 때는 `site-pages/` 가 없다.** 공개 사이트는 별도 저장소라
`ship-docs.sh` 가 자동으로 clone 한다. 수동으로 만들 필요 없다.

집 서버(게임 저장소)도 클라우드에는 없다. `sync-catalog.sh` 가 알아서 건너뛰고
공개 사이트만 갱신한다 — 정상 동작이니 오류로 보고하지 않는다.

---

## 원칙 — 이것부터 지킨다

1. **매일 문서를 쓰지 않는다.** 기술문서는 일간 주기의 대상이 아니다.
   판정 결과 아무것도 없으면 **아무것도 하지 않고 그렇게 보고한다.** 채우지 않는다.
2. **수치는 기억으로 쓰지 않는다.** 계산하거나 1차 출처로 확인한다.
   과거에 RF-DETR 수치와 speculative decoding 식을 기억으로 썼다가 틀린 전례가 있다.
3. **검증을 통과하지 못하면 배포하지 않는다.** `ship-docs.sh` 가 알아서 멈춘다.
4. **공개 저장소다.** 로컬 경로·내부 IP·키가 들어가면 안 된다. 스크립트가 검사한다.

## 일간 — 판정 모드

`ai-daily` 루틴이 이미 뉴스를 모았다면 **그 결과를 재사용한다.** 다시 검색하지 않는다.
단독 실행이면 `archive/YYYY-MM-DD.md` 의 오늘치를 읽는다. 없으면 판정을 건너뛴다.

### 절차

1. 오늘 뉴스 항목을 `DOCS-BACKLOG.md` 의 **판정 기준**에 대조한다.
2. 해당하는 것만 대기열 표에 한 줄씩 추가한다. **근거(출처 URL)를 반드시 적는다.**
3. 해당 없으면 표를 건드리지 않는다.

### 판정할 때 확인할 것

기존 49편이 무엇을 다루는지 모르면 판정할 수 없다. 필요하면 확인한다.

```bash
python3 scripts/catalog.py          # 단계별 편수
grep -n "slug" scripts/catalog.py   # 전체 목록
```

특히 **"기존 문서에 이미 있는 내용인가"** 를 먼저 본다.
겹치면 `신규` 가 아니라 `갱신` 이다. 새 문서를 늘리는 것보다 기존 문서를 정확하게 두는 편이 낫다.

### 보고

- 대기열에 추가한 건수와 각각의 종류·우선순위
- 추가하지 않았으면 **"오늘은 문서에 영향을 주는 소식이 없었다"** 고 그대로 말한다

## 주간 — 반영 모드

### 1. 고르기

`DOCS-BACKLOG.md` 에서 우선순위 `높음` 부터 **1~2건**만 고른다.
대기열이 비었으면 **여기서 끝낸다.** 억지로 주제를 만들지 않는다.

`높음`(수치가 틀림·사실 오류)이 있으면 그것부터 처리한다. 틀린 문서가 그대로 공개돼 있는 상태이므로 급하다.

### 2. 사실 확인

작성 전에 반드시 한다.

- 수치가 나오면 `python3 -c` 로 직접 계산해 본다
- 논문 주장은 WebFetch 로 원문(arXiv 초록 이상)을 연다
- 최신 상황이 자주 바뀌는 주제(검출기 SOTA, 보안 권고, 모델 스펙)는 웹으로 재확인한다
- **출처가 서로 어긋나면 그 사실을 문서에 적는다.** 한쪽을 골라 단정하지 않는다

### 3. 작성

**갱신**이면 기존 생성기를 고친다. 문서 HTML 을 직접 편집하지 않는다 — 다음 빌드에 덮어써진다.

```bash
cd scripts/docs
# gen_<주제>.py 수정
python3 gen_rf_detr.py
python3 check.py ../../site-pages/docs/rf-detr.html
```

**신규**면 기존 생성기 하나를 본떠 새로 만들고 `catalog.py` 의 `DOCS` 에 등록한다.

```python
("제목", "부제", "", "slug", "단계id", "한 줄 요약", "YYYY-MM-DD"),
#                 ↑ 직접 쓴 문서는 uuid 를 빈 문자열로 둔다
```

문서 포맷은 기존 49편과 같아야 한다 — 번호 절 · `.eq` 수식 블록 ·
손으로 짠 SVG + `figcaption` · `.note` 강조 · arXiv 인용 · 편별 팔레트 · 평서체.
팔레트는 편마다 다르게 잡되 라이트/다크 양쪽을 정의한다.

### 4. 배포

```bash
./scripts/ship-docs.sh "메시지"            # 검증 → 동기화 → 커밋 → 푸시
./scripts/ship-docs.sh --dry-run "메시지"  # 검증까지만
```

5단계 검증(카탈로그·문서 점검·상호링크·유출 스캔)을 전부 통과해야 커밋한다.
**실패하면 고치고 다시 돌린다. 검증을 건너뛰지 않는다.**

### 5. 기록

- `DOCS-BACKLOG.md` 의 해당 줄 상태를 `완료 YYYY-MM-DD` 로 바꾸고 커밋 해시를 적는다
- `RUNLOG.md` 에 한 줄 추가한다
