# AI Daily Routine

매일 AI 뉴스를 정리하고, **기술 문서를 하루 한 편씩** 늘려가는 루틴입니다.

- 공개 사이트 → **https://fogfog2.github.io/ai-concepts/**
- 사이트 저장소 → `fogfog2/ai-concepts` (결과물 HTML)
- 이 저장소 → 루틴 본체 (스킬 · 카탈로그 · 생성기 · 스크립트)

---

## 시작점은 ROUTINE.md 하나

Claude 는 **[ROUTINE.md](ROUTINE.md) 만 읽고 수행**합니다.
루틴 동작을 바꾸고 싶으면 그 파일만 고치면 됩니다. 스크립트는 건드릴 필요 없습니다.

```
ai-daily-routine 저장소의 ROUTINE.md 를 읽고 그대로 수행해줘
```

---

## 무엇을 하는가

**매일 두 가지**를 합니다. 서로 독립이라 한쪽이 부실해도 다른 쪽은 그대로 돕니다.

| | 하는 일 | 결과물 |
|---|---|---|
| **[A] 데일리 뉴스** | 확인된 당일 AI 소식 정리 | `archive/YYYY-MM-DD.md` → 사이트 소식 |
| **[B] 기술 문서** | **매일 1편** 새로 작성 | `site-pages/docs/<slug>.html` → 개념 지도·문서 목록 |
| **[C] 추천·벤치마크** | 추천 주제 갱신, 1차 출처의 에이전트 평가 확인 | `recommendation.json` · `benchmarks.json` → 사이트 |

### 문서 주제는 어떻게 고르는가

가장 좋은 후보는 **기존 문서가 여러 번 언급했는데 전용 문서가 없는 것**입니다.
이미 맥락이 깔려 있어 링크로 이을 곳이 많기 때문입니다.

기존 글에서 자주 언급하지만 설명을 따로 찾기 어려운 개념을 우선합니다. 이번에 추가한 U-Net은 CNN·분할·확산 모델 문서와 양방향으로 연결했습니다.

후보 목록은 [DOCS-BACKLOG.md](DOCS-BACKLOG.md) 에 있고, **vision 분야를 우선**합니다.

### 문서끼리 잇는다

낱개로 두지 않습니다. 새 문서를 쓰면 **양방향으로** 링크합니다.

- 새 문서 → 기존 문서 (선행 개념)
- 기존 문서 → 새 문서 ← **자주 빠뜨리는 쪽**. 언급만 하고 지나간 곳에 링크를 건다

## 폴더 구조

```
ROUTINE.md            ← 유일한 진입점. 이것만 고치면 된다

RUNLOG.md             ← 실행 기록

.claude/skills/       ai-daily · ai-docs (ROUTINE.md 를 보조)

scripts/
  catalog.py          85편 / 9단계 단일 출처
  sync-catalog.sh     카탈로그·뉴스·추천·벤치마크 → 사이트 데이터
  build-news.py       archive/*.md → news.json (사이트 상단)
  build-docs.py       문서에 상단 네비·목차 스크립트 주입 (멱등)
  build-recommendation.py / build-benchmarks.py  사이트 데이터 검증·복사
  ship-docs.sh        검증 6단계 → 커밋 → 푸시
  docs/
    build.py          팔레트 + 본문 → 완성 HTML
    _shell.css        전 편 공통 CSS
    check.py          태그·테마·SVG 접근성·미정의 변수 점검
    gen_*.py          편별 생성기
```

## 기술문서 — 9단계 85편

분류는 **파이프라인 단계**입니다. 모델이 만들어져 서비스되기까지의 순서라
겹침이 거의 없고, **순서 자체가 읽는 순서**가 됩니다.

| # | 단계 | 성격 | 편수 |
|---|---|---|---|
| 01 | 기초 | 모든 모델의 밑바닥 부품 | 5 |
| 02 | 아키텍처 | 무엇을 쌓을 것인가 | 11 |
| 03 | 학습 | 어떤 과제로 가르칠 것인가 | 13 |
| 04 | 적응·정렬 | 학습된 모델을 길들이기 | 7 |
| 05 | 추론 최적화 | 같은 모델을 싸고 빠르게 | 10 |
| 06 | 학습 인프라 | 어떻게 굴리는가 | 5 |
| 07 | 응용·시스템 | 실제로 쓰이는 형태 | 10 |
| 08 | 평가·안전 | 잘 됐는지 어떻게 아는가 | 7 |
| 09 | 특집 — 객체 검출 | 손으로 정하던 것을 학습으로 | 17 |

문서 포맷은 **번호 절 · 수식 블록 · 손으로 짠 SVG + 캡션 · arXiv 인용 ·
편별 팔레트 · 라이트/다크 양쪽 · 평서체**입니다.

## 문서 추가·수정

`scripts/catalog.py` 가 **단일 출처**입니다.

```python
("제목", "부제", "", "slug", "단계id", "한 줄 요약", "2026-08-11"),
#                 ↑ 직접 쓴 문서는 uuid 를 빈 문자열로
```

**HTML 을 직접 편집하지 않습니다.** 다음 빌드에 덮어써지므로 생성기를 고칩니다.

```bash
cd scripts/docs
python3 gen_lora.py                                 # 렌더
python3 check.py ../../site-pages/docs/lora.html    # 점검
```

## 배포

**GitHub Pages 하나뿐입니다.** 집 서버·로컬 서버·Tailscale·앱 내장 사본은 쓰지 않습니다.

```bash
./scripts/ship-docs.sh --dry-run "메시지"   # 검증까지만
./scripts/ship-docs.sh "메시지"             # 통과하면 커밋·푸시
```

자동 실행되는 루틴이라 **사람이 확인하지 않는다는 전제**로 짰습니다.
아래 중 하나라도 실패하면 **커밋하지 않고 멈춥니다.**

```
1. 카탈로그 검증   중복 slug · 미정의 단계 · 빈 단계
2. 동기화          artifacts.json · 네비 주입
3. 문서 점검       태그 균형 · 테마 3중 정의 · SVG 접근성 · 미정의 CSS 변수
4. 내부 상호링크   깨진 링크 0건인지
5. 카탈로그 정합성 카탈로그와 HTML 편수 일치
6. 유출 스캔       내부 IP · 로컬 경로 · 키
```

공개 사이트(`ai-concepts`)는 별도 저장소이며, 없으면 `ship-docs.sh` 가 자동으로 clone 합니다.
