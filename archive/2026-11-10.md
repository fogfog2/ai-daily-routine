## AlphaProof Code 공개 — Gemini 에이전트가 Signal의 지정 보안 속성을 Lean으로 검증

- 분류: `연구`

검증 대상은 libsignal 0.105.4의 일대일 세션을 중심으로 한 PQXDH·Triple Ratchet의 지정 보안 속성이다. 그룹 메시징은 후속 과제로 남는다. 사람이 정한 명세·암호학 가정·Lean 커널 등 신뢰 기반에 의존하며 Signal 앱 전체에 결함이 없다는 증명은 아니다.
공식 프로젝트에 기술보고서·Lean 개발 결과와 공개 저장소를 제공한다. 증명 생성물을 별도 검사기로 확인하는 구조이며 모델이 스스로 성공이라고 말한 결과와 구분한다. 이번 수집에서 대규모 증명을 다시 실행한 것은 아니다.

그래서: 코드 생성 에이전트의 결과를 테스트뿐 아니라 지정 속성의 기계 검증으로 연결하는 구체적인 사례다. 보증을 읽을 때 대상 빌드·명세·가정·검증 범위를 함께 확인해야 한다.

## Tree-Ising 논문 — Weight-Space Programming의 루프 수리를 이산 최적화로 대체

- 분류: `연구`
- 출처: https://arxiv.org/abs/2611.14210v1

11-10 15:32:04 UTC 제출된 사전공개 논문은 Qwen의 추론 반복 문제를 BF16 가중치의 부호 뒤집기·지수 이동으로 수리하는 Tree-Ising을 제안한다. LLM 에이전트의 직접 가중치 편집 대신 행별 QUBO를 GPU의 simulated annealing·simulated bifurcation으로 푼다.
저자의 동일 하네스 재평가에서 Qwen3.5-0.8B의 MATH-500@4는 agent 편집 51.7%·Tree-Ising 54.6%였다. @4는 문제당 4개 생성의 평균 정확도이며 하나라도 맞으면 성공인 pass@4와 다르다. base 7.9%는 원 연구에서 인용한 수치로 이 논문의 동일 하네스 재측정은 아니다.
고정 레시피 한 번 실행에는 forward-pass 요청 4회·LLM 생성 토큰 0개와 GPU 비용 약 $0.90을 보고했다. 기존 에이전트가 선택한 두 층·공개 로그를 활용하며 양쪽 방법 개발 비용은 제외했다. 동등한 탐색 정보·예산으로 처음부터 수리법을 발견한 비용 비교는 아니다.
평가는 한 모델 계열의 두 크기·수학 문제·단일 생성 seed에 한정된다. 초기 개발에 노출된 MATH-500 100문제가 전체 결과에 포함되며 저자는 별도 미노출 400문제 분석도 제시한다. 범용 능력·지시 이행·부작용까지 검증한 결과나 양자 계산 우위로 일반화할 수 없다.

그래서: 직접 가중치 편집을 탐색한 뒤 특정 실패 모드의 고정 최적화 레시피로 옮길 가능성을 보여준다. 비용 수치보다 사전 지식·선택된 층·평가 노출과 다른 능력의 보존 여부를 함께 검토해야 한다.

## 에이전트 벤치마크 포화 재분석 — 성공 여부·해결 품질·비용을 따로 평가하자는 제안

- 분류: `연구`
- 출처: https://arxiv.org/abs/2611.13541v1

11-10 04:03:04 UTC 제출된 사전공개 논문은 8개 벤치마크의 공개 실행 기록 등을 재분석해, 과제가 남아 있어도 이진 pass/fail·기준 정답에서 잘리는 점수가 상위 모델 차이를 가릴 수 있다고 주장했다. 최신 모델의 새 종합 순위를 발표한 연구가 아니다.
ALE-Bench의 같은 실행들을 연속 점수로 평가하면 상위 10개가 3개 통계적 집단으로 나뉘지만, 인간 중앙값을 넘었는지만 확인하면 한 집단으로 묶인다고 보고했다. 기준선을 더 높이는 것만으로 모든 능력 구간의 구분력이 해결되지는 않는다는 분석이다.
Terminal-Bench 일부 13개 과제는 4개 모델·3회씩 총 156회 재실행했다. Terminus-2·제3자 게이트웨이에서 GPT-5.3-Codex·Opus 5·Astra·Gemini 3.1 Pro를 비교했으며 통과 여부가 같은 실행도 프로그램 최적화량 등이 달랐다. 최신 Claude/Codex의 동일 effort 추론 속도 비교가 아니다.
저자는 통과 조건과 연속 품질 목표, 비용을 분리하고 날짜·버전이 고정된 기준점으로 점수화할 것을 제안한다. 작은 재실행 표본·공개 로그의 불완전성·판정기 오류·목표 지표 악용 가능성도 한계로 남긴다. 품질 지표를 기록하지 않은 과거 실행을 모두 복구할 수는 없다.

그래서: 모델 선택에서 성공률의 작은 차이만으로 순위를 확정하기보다 오차·산출물 품질·작업당 비용과 effort·하네스를 함께 봐야 한다. 기존 성능 비교의 빈칸을 이 재분석 결과로 채워서는 안 된다.
