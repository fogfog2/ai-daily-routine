## Claude Fable 5.2·Mythos 5.2 출시 — 요금·속도·effort별 코딩 결과 공개

- 분류: `모델`
- 출처: https://www.anthropic.com/claude-fable-and-mythos-5-2

Anthropic은 11-09 같은 기반 모델을 쓰는 Fable 5.2와 Mythos 5.2를 발표했다. Fable은 Claude·API·주요 클라우드에 제공되며, Mythos는 사이버·생명과학 검증 프로그램의 조직 승인이 필요하다. API 사양은 1M 문맥·최대 128k 출력이다.
표준 API 요금은 100만 토큰당 입력 $8·출력 $40, fast는 $16·$80다. 공급사는 이전 5.1 대비 출력 생성 최대 30% 가속, fast에서 표준 대비 토큰 생성 최대 2.5배를 제시했다. 작업 전체 완료 시간의 배속이나 독립 측정값은 아니다.
앱·Claude Code의 기본 effort는 medium이다. 공급사 FrontierCode 2.0에서 Fable high 45.3%는 Opus 5.5 max 45.5%와 비슷하면서 작업당 비용이 약 절반이며, Fable xhigh는 49.1%였다. 비교된 Astra 최고 effort 42.8%도 같은 발표의 수치다. 동일 effort·하네스의 독립 비교나 Sol·Luna·Sonnet까지 포함한 순위가 아니다.
안전 모니터링용 데이터 보관은 일반적으로 30일이다. 고객 인프라에서 모니터링하는 Enterprise Frontier Safeguards는 비공개 베타이며, ZDR은 별도 승인 조건이 있다. 모델 출시와 모든 고객의 ZDR 지원을 동일시하지 않는다.

그래서: medium에서 실제 작업 비용·완료 시간을 먼저 측정하고 어려운 작업에 high·xhigh를 시험할 근거가 생겼다. 공급사 벤치마크의 effort와 비용 조건을 유지해 비교해야 한다.

## Claude Code 2.1.321 안정판 — Fable 5.2 연결과 MCP·Bash 권한 검사 수정

- 분류: `도구`
- 출처: https://github.com/anthropics/claude-code/releases/tag/v2.1.321

11-09 UTC 공개된 2.1.321 안정판은 Fable 계열 기본 모델을 Fable 5.2로 갱신했다. 1M 문맥, 100만 토큰당 입력 $8·출력 $40·캐시 읽기 $0.20을 명시했다. 전체 기본 모델이 Fable로 바뀌었다는 뜻은 아니다.
MCP OAuth 리디렉션 시 refresh token 등 비밀이 다른 호스트로 전송되던 문제, 샌드박스 밖 읽기 전용 Bash의 확인 누락, 잘못된 작업 폴더 기준 쓰기 권한 검사, cp·mv 대상 파일의 deny·보호 확인 누락을 수정했다.
remote-control에 --settings <file>을 추가해 시작하는 각 세션에 설정을 적용한다. 설정 파일이 바뀌면 remote-control을 재시작할 때까지 새 세션을 시작하지 않는다. 일부 플래그 조합에서 claude agents의 --model·--effort 등이 무시되던 문제도 고쳤다.
fast 제공이 과부하·한도·오류로 실패할 때 다른 모델로 바꾸기 전에 같은 모델의 표준 속도를 먼저 시도하도록 수정했다. git status 실패를 깨끗한 작업 트리로 잘못 보고하던 표시도 unavailable로 바꿨다.

그래서: 모델 추가뿐 아니라 OAuth 비밀 보호·파일 쓰기 승인·effort 적용을 바로잡은 업데이트여서, MCP와 원격 세션을 사용하는 환경의 갱신 가치가 크다.

## OpenAI Control Room 공개 — 연구 에이전트 추론을 중앙에서 중단하는 인프라

- 분류: `도구`
- 출처: https://openai.com/index/control-room/

OpenAI는 11-09 연구 인프라의 학습·평가·데이터 처리 등 모델 추론 작업을 추적하고 중단하는 Control Room을 설명했다. 내부 연구 인프라에는 이미 배포됐으며 일반 고객용 Codex·API 기능의 정식 출시 발표가 아니다.
작업은 승인된 안전성 근거와 연결된 job_id를 받고, 추론 엔진은 요청마다 해당 작업의 실행 허가를 확인한다. 중단 판정은 자주 바뀌는 작업 코드의 자발적인 종료 처리에 의존하지 않고 추론 계층에서 적용한다.
회사는 중단 지시가 도착한 뒤 모델 출력이 멈추기까지 최대 35초라고 밝혔다. 허가 캐시 때문에 생기는 지연이며 위험 발생부터 탐지까지의 시간이나 외부 도구·프로세스 전체 종료 보장이 아니다. 연구 프로세스 자체는 살아 있을 수 있다.
Control Room 장애 때 추론 요청을 거부하는 fail-closed는 최전선 모델 연구 작업에 적용됐고, 나머지 연구 작업은 며칠 내 적용을 마칠 예정이라고 구분했다. 공급사의 구현 설명이며 독립적인 안전성 검증 결과는 아니다.

그래서: 장기 실행 에이전트의 중단 권한을 개별 에이전트 코드와 분리하고, 추론 허가 만료·장애 시 거부·외부 작업 취소를 각각 설계하는 참고 사례다.

## Google TPU 8tx·8i Max 발표 — Claude Code 연동 TPU 에이전트는 Preview

- 분류: `시스템`
- 출처: https://blog.google/innovation-and-ai/infrastructure-and-cloud/global-network/tpu-8i-max-and-8tx/

Google은 11-09 8세대 TPU 시스템 8tx와 8i Max를 발표했다. 8tx는 8t와 같은 실리콘에 5세대 AMD EPYC 호스트·Boardfly 네트워크를 결합해 사용 중인 데이터·가중치 보호와 기밀 추론을 겨냥한다. 새 시스템 발표와 새 실리콘 설계를 구분했다.
8i Max는 패키지 하나에 8i 칩 두 개를 넣어 단일 8i 대비 연산·SRAM·HBM 대역폭이 각각 2배라고 설명했다. 이는 공급사 구성 수치이며 에이전트의 작업 성공률이나 완료 속도 2배를 뜻하지 않는다.
새 오픈소스 TPU agent suite는 Preview로, Claude Code·Cursor·Google Antigravity에서 TPU 도입·병목 진단·커널 자동 튜닝을 지원한다. Python에서 학습한 모델을 TPU·GPU·CPU의 C++ 런타임으로 제공하는 XLA Serving Engine도 소개했다.
별도로 Cloud Pathways와 GKE dynamic slicing은 정식 제공이라고 명시했다. 반면 하드웨어 발표·TPU 도구 Preview를 모두 정식 제공으로 묶지 않았고, 지난달 공개한 TorchTPU를 오늘 처음 공개한 기술로 다시 쓰지 않았다.

그래서: Claude Code로 TPU 최적화를 시도할 개발 경로가 추가됐다. 도구의 Preview 상태와 인프라 제공 상태를 나눠 검토하고 실제 모델·문맥 길이의 비용과 지연으로 판단해야 한다.
