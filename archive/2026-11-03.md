## Claude Code 2.1.317 — 모델별 하위 effort·프로젝트 설정 적용·훅 실패 처리 개선

- 분류: `도구`
- 출처: https://github.com/anthropics/claude-code/releases/tag/v2.1.317

Anthropic은 11월 3일 01:25:46 UTC, 한국시간 11월 3일 10:25에 Claude Code 2.1.317 안정판을 공개했다. 앱이 미리 시작한 세션을 프로젝트에서 열 때 effortLevel이 무시되던 문제를 수정했다.
주 대화와 다른 모델을 쓰는 서브에이전트·팀원은 세션 effort 대신 해당 모델에 저장된 effort 또는 기본값을 사용하도록 바꿨다. VS Code에서 telemetry를 껐을 때 ultrathink가 해당 턴의 effort를 높이지 못하던 문제도 수정했다. 새 모델 출시나 동일 effort의 성능 향상 결과와 구분한다.
Agent SDK 훅 콜백에 onFailure: "block"을 추가해 콜백 실패 때 행동을 막을 수 있게 했다. /schedule은 요청하지 않은 커넥터가 붙을 때 경고하고 제거 방법을 안내하며, 예약 작업 생성·변경 결과에 다음 실행 시각·링크가 빠지던 문제를 고쳤다.
디스크·할당량 문제로 기록 저장이 실패한 claude -p가 성공 코드 0을 반환하던 동작을 수정했지만 일부 NFS 용량 부족은 놓칠 수 있다고 명시한다. OTel에 플랜·좌석·공급자 등의 식별 항목과 앱 게이트웨이 과거 비용 보고를 추가했다. 클라이언트 계측·복구 변경을 모델 벤치마크와 섞지 않는다.

그래서: Claude·Codex 비교 시 상위 세션의 effort만 적으면 하위 작업의 실제 설정을 놓칠 수 있다. 모델별 적용 수준·훅 실패·예약 결과·전체 비용을 함께 기록하고 자동화의 성공 판정을 확인해야 한다.

## OpenAI, Astra 물리 설계 사례 공개 — 제조 검토와 내부 평가 조건 명시

- 분류: `연구`
- 출처: https://openai.com/index/accelerating-engineering-for-the-physical-world/

OpenAI는 11월 3일 Astra·Codex를 이용한 기구·전기 설계와 시뮬레이션 사례를 공개했다. 새 Astra 모델의 일반 출시가 아니라 내부 사용·초기 산업 협업의 진행 상황이다.
팀원 두 명이 부업 프로젝트로 Astra와 일주일 이내에 Codex 대화용 장치의 외함·PCB·소프트웨어를 설계하고 계약 제조사가 한 달 이내에 소량 시제품을 만들었다고 밝혔다. 제조 제약·공차·조립 세부 사항을 일관되게 반영하지 못해 여러 차례 검토·수정이 필요했다고 구분한다. 일반 판매 제품이나 무감독 제조 완료를 뜻하지 않는다.
BenchCAD 2.0에서 새 내부 모델의 평균 점수 0.875와 최고 reasoning 설정의 GPT-6 Astra 0.594를 제시했다. 공급사 평가이며 새 내부 모델의 이름·일반 제공이나 Claude·Sol·Luna와 동일 effort의 독립 비교를 발표한 것은 아니다.
Chip Ganassi Racing과 스캔에서 편집 가능한 CAD·제조 도면으로 이어지는 작업을 시험하고, Mazda와 공기역학·충돌 안전 연구 협업을 발표했다. 협업 엔지니어가 정확성과 제조 가능성을 검토하며 시뮬레이션·초기 연구를 양산 성과로 해석하지 않는다.

그래서: Codex 활용 범위가 코드 작성에서 CAD·전자 설계·시뮬레이션으로 넓어지는 사례다. 도입 비교에서는 생성 결과뿐 아니라 제약 충족·전문가 수정량·검증 비용을 측정해야 한다.
