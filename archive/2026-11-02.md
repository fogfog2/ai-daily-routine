## FlashProve 연구 프로토타입 공개 — 응답을 생성한 모델의 추론을 증명

- 분류: `연구`
- 출처: https://www.anthropic.com/research/provable-inference

Anthropic은 11월 2일 zkSNARK 기반 추론 증명 연구 프로토타입 FlashProve를 공개했다. 지정한 모델 가중치가 계산에 사용됐는지 확인하는 접근으로 코드·프로토콜·Lean 증명·기술 보고서를 공개한다. 답변의 사실성이나 모델 능력을 증명하는 제품은 아니다.
Llama 4 Maverick 400B MoE의 4비트 가중치·정수 연산 조건에서 H100 한 장으로 초당 약 110토큰의 증명을 생성하고 1,024토큰 요청의 증명 크기는 약 19 MB라고 보고했다. 같은 모델을 vLLM으로 실행하는 것보다 GPU 시간이 약 70~95배 더 든다는 공급사 측정이며 일반 추론이 110토큰/초 빨라졌다는 뜻이 아니다.
현재 증명 범위는 최대 1,024토큰 문맥의 정수 모델·greedy decoding이다. 부동소수점 실행이나 sampling 결과와 일치한다는 보장이 아니며 가중치는 숨기지만 아키텍처를 숨기는 것은 목표가 아니다.
Lean의 프로토콜·보안 성질과 느린 검증기를 제공하지만 빠른 C++ 실행 코드 전체에 형식적 보증을 제공하지는 않는다. 연구 중간 결과이며 현재 Claude API·Codex 응답에 이미 이 증명이 붙는 정식 서비스로 소개하지 않는다.

그래서: 모델 라우터가 약속한 모델을 실제로 제공했는지 확인하는 기술 후보가 된다. Claude·Codex 성능 비교에서 모델 식별의 신뢰 문제와 추론 품질·effort·비용 문제를 나눠 볼 수 있다.

## StateBench 논문 공개 — Claude·GPT·Gemini의 장문 상태 추적을 난도별 평가

- 분류: `연구`
- 출처: https://arxiv.org/abs/2611.03094

StateBench 논문 v1은 11월 2일 13:12:15 UTC에 공개됐다. Ai2의 11월 3일 소개 글도 대조했지만 같은 연구를 두 번 게시하지 않고 원래 논문 날짜에 기록한다. 긴 입력에서 변수·사람·물건의 상태 변화와 최종 값을 추적하는 능력을 평가한다.
문제를 값 고정·새 값 대입·자기 값에 의존한 갱신·다른 변수 참조가 가능한 네 단계로 나눈다. 마지막 값 검색만 필요한 과제와 이전 변화들을 누적해야 하는 과제를 구분해 평가하는 설계다.
저자들은 Gemini 3.8 Flash·Claude Opus 5.5·GPT-6 Sol·Luna가 쉬운 두 단계에서는 잘했지만 긴 자기 참조·일반 유한 상태 과제에서 성능이 크게 떨어졌고, 가장 긴 일반 유한 과제는 모두 정확도 13% 이하였다고 보고했다. 이 연구의 설정과 과제에 한정한 외부 연구 결과이며 최신 제품 에이전트 전체의 같은 effort 순위는 아니다.
별도로 직접 학습한 작은 recurrent·hybrid 모델이 긴 변화열에 더 잘 일반화한 실험도 제시한다. 과제 직접 학습과 사전 학습 모델 평가를 섞지 않는다. 현재 프레임워크는 변수 수가 고정돼 실제 대화에서 새 개체가 늘어나는 상황까지 포괄하지 않으며 이번 회차에서 재현하지 않았다.

그래서: 긴 문맥 창만으로 장기 에이전트가 상태를 정확히 유지한다고 가정할 수 없다. 실제 업무의 갱신·취소·변수 참조를 포함한 과제를 만들고 모델·effort·문맥 길이별로 최종 상태 오류를 따로 측정할 근거가 된다.

## DR Pixel — OCR 텍스트 대신 논문 페이지 이미지를 검색·추론하는 연구 공개

- 분류: `비전`
- 출처: https://arxiv.org/abs/2611.03097

DR Pixel 논문 v1은 11월 2일 13:13:42 UTC에 공개됐다. 표·그림·수식이 있는 과학 논문을 OCR 텍스트로만 줄이지 않고 렌더링한 페이지 이미지 단위로 검색하고 읽는 멀티모달 deep research 에이전트다.
공식 GitHub는 99,055편·1,062,153페이지의 코퍼스와 500문항 DRPixelBench를 설명한다. 같은 논문 집합의 페이지 검색과 OCR 기반 검색을 비교하며 기본 설정은 질문당 검색 최대 20회·페이지 검색 상위 3개다. 평가 하네스·학습 코드·데이터·학습 모델을 공개한다고 안내한다.
저자는 GPT-5.4·Gemini 3.5 Flash·Qwen3.6-27B 등의 비교에서 페이지 기반 접근이 OCR 기준선보다 좋았고 검색 호출이 적었다고 보고했다. reasoning·검색 단계의 기여도에 따라 학습 가중치를 주는 counterfactual credit reweighting으로 자체 벤치마크의 검색 재현율은 약 15%p·최종 정확도는 10%p 이상 높였다는 저자 실험이다.
OpenAI 호환 엔드포인트용 하네스가 있지만 현재 Claude·Codex 제품이나 최신 모델의 동일 effort 우열을 검증한 결과는 아니다. 수치의 데이터·검색 예산·채점 조건을 유지해 읽어야 하며 이번 작업에서는 모델 실행·학습·재현을 수행하지 않았다.

그래서: 표·도표·수식 중심의 연구 자료라면 OCR 정확도만 높이는 것 외에 페이지 이미지 검색을 비교할 수 있다. 자신의 문서에서 검색 성공률·답변 정확도·이미지 토큰·검색 비용을 함께 측정해야 한다.

## Claude message threads 베타 — 새 메시지만 전송, 서버 대화는 단기 보관

- 분류: `도구`
- 출처: https://platform.claude.com/docs/en/build-with-claude/message-threads

Anthropic은 11월 2일 Messages API의 message threads 베타를 발표했다. message-threads-2026-08-12 헤더를 사용하며 헤더의 8월 날짜가 발표일은 아니다. Claude API·Claude Platform on AWS·Anthropic 관리형 Google Cloud·Microsoft Foundry에서 제공한다고 안내한다.
처음에 system·tools·대화 전체를 보내고 이후에는 새 메시지와 직전 응답 id만 보낸다. API가 대화를 다시 구성해 모델을 호출한다. 공급사는 긴 에이전트 루프의 업로드·검증·토큰화 작업이 줄어 첫 토큰 지연이 낮아진다고 설명하지만 독립 측정값이나 새 모델 성능 점수를 발표한 것은 아니다.
스레드는 마지막 요청 후 5분에 만료되고 마지막 사용 후 최대 1시간 안에 삭제한다. 저장은 best-effort이며 이어갈 수 없으면 404 오류가 나므로 앱이 대화 원본을 보관하고 새 create 요청으로 전체를 재전송하는 복구 경로가 필요하다. 영구 메모리나 장기 세션 저장소가 아니다.
스레드가 프롬프트를 자동으로 캐싱하지는 않으며 cache_control 등 기존 캐시 설정은 별도다. 전송량 감소를 문맥 전체의 입력 토큰 무료화나 단가 인하로 해석하지 않는다. 공식 문서는 ZDR·HIPAA 대상이 아니라고 구분한다.

그래서: 긴 Claude API 에이전트의 전송 지연을 줄이는 실험 후보가 생겼다. Claude·Codex 비교에서는 모델·effort를 고정하고 첫 토큰 지연·전체 작업 시간·캐시·총비용을 나눠 측정하며 만료와 재전송도 시험해야 한다.

## Gemini 2.5 Pro·Flash 지원 중단 예고 — 12월 1일 모델·요율 자동 전환

- 분류: `모델`
- 출처: https://aistudio.google.com/docs/changelog

Google은 11월 2일 Gemini 2.5 Pro·2.5 Flash를 deprecated로 지정하고 Google AI Studio에서 더 이상 선택할 수 없다고 공지했다. 이번 공지는 새 Gemini 모델 출시가 아니라 기존 모델의 지원·이전 정책 변경이다.
2026년 12월 1일부터 gemini-2.5-pro API 요청은 gemini-3.8-flash로, gemini-2.5-flash 요청은 gemini-3.5-flash-lite로 자동 연결하고 각각 대상 모델의 요율을 적용한다고 안내한다. 11월 2일에 API가 이미 모두 자동 전환됐다는 뜻은 아니다.
Google은 12월 1일 전에 모델 문자열을 직접 바꾸고 이전 가이드를 검토하라고 권고한다. 기존 2.5 단가·응답 특성이 계속 유지된다고 가정할 수 없으며 전환 뒤 실제 모델과 청구를 확인해야 한다.
공식 변경 기록은 function calling·thought_signature 검증, thinking_budget에서 thinking_level로의 전환, 일부 sampling 파라미터와 미리 채운 모델 턴 제거를 호환성 변경으로 명시한다. 같은 요청을 새 모델로 보내는 것만으로 기존 에이전트 동작이 보장되지는 않는다.

그래서: Gemini 2.5를 고정한 도구·에이전트는 기한 전에 함수 호출·추론 설정·출력·비용을 다시 검증해야 한다. Claude·Codex와 비교할 때 자동 연결된 새 모델을 옛 2.5 결과로 표시하지 않도록 실제 모델을 남겨야 한다.

그래서: Claude Code 등 도입 후 비용만 늘었는지, 리뷰·재작업·배포 흐름도 개선됐는지 함께 확인하는 운영 도구 후보가 된다. 도입 전 수집 가능한 도구·지표·권한 범위를 확인해 자신의 팀 데이터로 비교해야 한다.
