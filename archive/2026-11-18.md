## Codex 샌드박스 설계 설명 공개 — permission profile과 MCP 격리 범위

- 분류: `도구`
- 출처: https://openai.com/index/inside-the-codex-sandbox/

OpenAI는 11-18 Codex sandbox의 설계·설정·OS별 집행 방식을 설명하는 엔지니어링 글을 공개했다. 기존 기능의 구조와 사용법을 설명한 글이며 새 모델·격리 기능 전체의 당일 출시로 표시하지 않는다.
Git 저장소를 workspace로 둔 기본 :workspace profile은 작업 영역 쓰기를 허용하되 .git·.codex 같은 경로를 읽기 전용으로 보호하고 네트워크는 끈다고 설명한다. 파일 읽기는 OS 사용자 권한 아래 넓게 허용하므로 workspace 밖을 모두 못 읽는 구성과는 다르다.
stdio MCP 서버의 시작 명령은 필요한 자원을 추정하기 어려워 Codex가 기본 격리하지 않는다고 명시했다. 글은 codex sandbox --permission-profile로 서버 명령을 감싸 쓰기 경로·네트워크를 제한하는 예를 제시한다. Codex 셸 명령의 제한이 외부 MCP 서버에 자동 적용된다고 가정하면 안 된다.
permission profile은 파일·네트워크 제한을 OS 기제로 집행하며 네트워크 프록시가 도메인 규칙을 적용한다. 기업은 managed requirements로 선택 가능한 profile을 제한할 수 있다. 저자는 허용 경로 안의 유해 변경까지 sandbox만으로 모두 막을 수 없다고 설명한다.

그래서: 에이전트의 명령 실행과 외부 MCP 도구가 각각 어떤 권한으로 도는지 확인할 구체적인 안내다. 기존 개발 환경을 재사용하면서 필요한 파일·네트워크 접근만 주는 설정을 검토할 수 있다.
