OpenAI·Onava는 11-24 GPT-6 계열의 단백질 설계 연구를 공개했다. 연결 논문 표지도 11-24이며 사전 공개 버전 GPT-6.2의 실험과 별도 내부 연구 모델의 계산 평가를 구분한다. 논문: https://cdn.openai.com/pdf/gpt-6-a-universal-foundation-model-for-protein-biology.pdf
범용 추론·코드로 minibinder 골격을 생성하고 서열을 재설계했다. 실험 1은 GPT-6.2 골격에 SolubleMPNN 서열 제안과 전문 모델의 후보 선별을 더했고 5개 표적에 대한 322개 단백질 중 35개(10.9%)에서 결합 신호를 확인했다. 각 표적에서 최소 1개 hit가 있었으나 서로 다른 선별·결합 정의의 과거 RFdiffusion hit rate와 직접 순위를 매길 수 없다.
별도 실험의 미공개 골격 서열 재설계는 107개 중 14개(13.1%)가 결합했다. 항체 실험도 결합 유지가 관찰됐지만 이는 개발사·연구 파트너의 결과이며 일반 의약품 효능이나 Astra·Sol effort별 코딩 성능 평가가 아니다.
후보 선별에 구조 예측 전문 모델을 사용했으므로 전문 모델 없이 zero-shot으로 신규 minibinder를 끝까지 설계했다고 결론 내릴 수 없다. 전체 단백질 접힘 예측은 여전히 약점이고 일부 계산 평가에는 암기·구조 생성 흔적의 영향 가능성이 있다. 선택성·안정성·생물학적 작용·치료 안전성과 효능은 추가 검증 대상이다.

그래서: 자연어 제약과 코드로 분자 설계의 일부 단계를 수행하는 연구다. 실험 결합·계산 점수·내부 모델 결과를 분리해 읽어야 하며 새 치료제나 전용 설계 제품 출시로 해석하지 않는다.

## Codex·Astra로 공개 천문 자료 분석 — 외계행성 발견이 아닌 후보 후속 검증

- 분류: `과학`
- 출처: https://openai.com/index/searching-for-distant-planets-with-astra/

OpenAI는 11-24 두 아마추어 천문가가 Codex·Astra로 공개 관측 자료를 분석한 사례를 소개했다. OpenAI 엔지니어 Kevin Bond는 Kepler 약 10만 별을, 별도로 작업한 Ethan Byrd는 여러 공개 망원경 자료 약 1900만 별을 분석했다. 새로운 모델 출시나 독립 벤치마크 발표가 아니다.
Bond는 Codex로 기존 탐색 방법을 비교·결합하고 한 agent가 광도 곡선을 훑으면 다른 agent가 후보를 추가 검사하게 했다. 200개 이상 신호 중 기존 확인 행성 10개를 재검출했다. SETI Institute 천문가의 독립 탐색에서도 KIC 5689121·KIC 6691030의 같은 두 신호가 관찰됐다고 소개한다.
Byrd의 Astra 기반 탐색은 첫 단계에서 후보 49개를 얻었고 그중 강한 후보 하나를 TESS 연구진에 보내 후속 분석을 기다린다. SETI의 신호 재검출과 TESS의 검토 대기는 행성 확정과 다르며 전체 후보의 독립 검증이 완료된 상태가 아니다.
반복되는 밝기 감소는 쌍성·기기 변화 등으로도 생길 수 있다. 후속 관측·통계 검증·다른 관측 방식과 학술 검토가 필요하다. 글에는 모델별 effort·전체 비용·실행 시간의 통제 비교가 없어 Astra와 Claude의 성능 순위나 탐색 가속 배수를 만들지 않는다.

그래서: 자료 탐색→코드 실험→후보 재검사→외부 전문가 검증의 agent 활용 사례로 볼 수 있다. 유망한 신호를 찾았다는 사실과 새 외계행성을 확정했다는 주장은 구분한다.

> 추가 확인: 2026-11-27. 아래 Bonsai 2.5는 공식 글의 실제 공개일 11-24 소식이다. 11-26 수집 요약의 날짜로 바꾸지 않는다.

## Ternary Bonsai 2.5 27B 공개 — 3값 가중치 로컬 agent 모델과 xhigh 평가 조건

- 분류: `모델`
- 출처: https://prismml.com/news/bonsai-2-5-27b

PrismML은 11-24 Qwen3.8-27B 기반 Ternary Bonsai 2.5 27B를 Apache 2.0 가중치로 공개했다. 기존 Bonsai 2의 작은 크기를 유지하면서 다중 turn 도구 사용·코딩·과도한 thinking과 반복을 개선했다는 공급사 발표다. 모델 카드: https://huggingface.co/prism-ml/Ternary-Bonsai-2.5-27B-GGUF
3값(−1·0·+1) 중심 가중치·그룹별 scale 등으로 압축한 PTQ1_0 모델 파일은 약 5.93 GB·평균 1.76 bit/weight다. FP16 모델 파일 53.8 GB와의 비교이며 KV cache·실행 버퍼·이미지 구성요소 등을 포함한 전체 RAM/VRAM 최소 요구량이 5.93 GB라는 뜻은 아니다. 다른 파일 형식·MTP draft head 포함 여부도 크기를 바꾼다.
공식 백서의 동일 평가 경로·thinking xhigh에서 SWE-bench Verified는 기존 Bonsai 2 60.8→2.5 75.6, FP16 Qwen 기준은 80.6이었다. SWE-bench 500개와 DeepSWE는 mini-SWE-agent, Terminal-Bench 2.1의 89개는 Terminus-2로 평가했다. 공급사 pass@1 평가이며 실제 Claude Code·Codex 하네스나 모델별 모든 effort와 직접 비교한 결과는 아니다. 백서: https://github.com/PrismML-Eng/Bonsai-demo/blob/main/bonsai-2-5-27b-whitepaper.pdf
현재 공식 카드에서 Q2_0는 upstream llama.cpp, PTQ1_0·PQ2_0는 PrismML fork 등 형식별 실행 경로가 다르다. Apple용 MLX도 안내하지만 어느 형식이든 같은 속도를 보장하지 않는다. 백서는 여러 문맥 창에 걸쳐 수시간 실행하는 MLE/Vending/SWE-bench Pro 같은 장기 작업을 아직 측정하지 않았다고 명시한다.

그래서: 개인 장치에서 파일·도구를 다루는 agent의 메모리를 줄이는 공개 모델 선택지다. 작은 가중치 파일·검증된 코딩 점수·전체 실행 메모리와 장기 안정성을 구분해 실제 장치에서 확인해야 한다.
