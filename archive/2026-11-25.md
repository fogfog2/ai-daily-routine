## Claude Code 2.1.332 안정판 — MCP 서버 스킬 베타와 effort·세션 복구 수정

- 분류: `도구`
- 출처: https://github.com/anthropics/claude-code/releases/tag/v2.1.332

Anthropic은 11-25 01:32:14 UTC / 한국시간 10:32:14에 2.1.332 안정판을 게시했다. MCP 서버가 제공하는 스킬을 server:skill 이름으로 / 메뉴에 표시하는 기능은 베타다. PreSkillShellCommand hook으로 스킬·명령 로드 중 inline shell 실행을 거절할 수 있고 이 hook 설정을 2.1.331 이하에서 쓰면 시작 대화상자가 나타나는 호환성 조건이 있다.
--environment로 interactive 세션을 시작하며 CLAUDE_CODE_EFFORT_LEVEL이 같은 수준으로 설정된 경우 --effort가 무시되던 문제를 고쳤다. 반복 auto-compaction 실패 뒤 문맥 한도에서 Prompt is too long으로 끝나던 경우와 잘린 요약 재시도, crash·kill 뒤 제3자 공급자 세션 재개 시 마지막 메시지 유실도 수정했다. 모델의 새로운 benchmark 점수나 effort별 성능 상승 발표는 아니다.
출력 폭주 로컬 MCP·hook의 무한 출력·큰 로그 처리로 멈추던 여러 경우를 수정했다. SSE MCP의 event stream이 다른 endpoint로 복구되거나 사라진 뒤 호출이 계속 실패하던 문제, Remote Control 재시작 뒤 로컬 MCP session ID가 바뀌던 문제도 포함한다.
Bedrock Mantle의 sonnet alias가 Haiku 4.5로 잘못 해석되던 것을 수정했다. 이제 Sonnet 5를 뜻하며 Sonnet 5.5는 아니다. 계정에 Sonnet 5 접근이 없으면 오류이므로 활성화가 필요하다. 다른 공급자에서도 관리자 허용 모델·fallback 선택 관련 수정을 했지만 모든 공급자에 같은 alias 규칙을 적용한다고 일반화하지 않는다.

그래서: 서버 배포 스킬과 세션·도구 복구가 실제 운영에 영향을 준다. CLI 안정판과 스킬 베타를 구분하고 effort 적용·모델 alias를 확인한 뒤 기존 작업에 적용할 수 있다.

- 분류: `시스템`
- 출처: https://huggingface.co/blog/inkling-2-mini-inference-hillclimb

Hugging Face의 Niels Rogge는 11-25 Inkling 2 Mini를 RTX PRO 6000 96 GB 한 장에서 튜닝한 agent 활용 사례와 로그·배포 설정을 공개했다. 모델의 최초 출시를 오늘로 바꾸지 않는다. 공식 실험 저장소: https://github.com/NielsRogge/inkling-2-mini-hillclimb
46개 유효 benchmark run에서 기준 SGLang·추측 디코딩 없음 대비 vLLM nightly·DSpark 구성의 단일 사용자 decode는 약 136→190.6 token/s(약 40%), 8사용자 합산 decode는 약 570→716 token/s(약 26%)로 보고했다. 이는 저자 측 해당 GPU·서빙 설정의 출력 속도이며 코딩 agent의 정답률·작업 완료 시간 개선이나 모든 하드웨어의 결과는 아니다.
6개 고정 prompt·temperature 1.0·thinking on·출력 512-token 조건과 추측 디코딩의 12회 반복을 썼다. 후보 앞뒤의 control run으로 검증하고 warmup·JIT·엔진 변동성을 점검했다. 최종 설정은 draft 7개·probabilistic sampling·max-model-len 262144·gpu-memory-utilization 0.85이며 이미지 digest와 모델 revision을 고정했다.
검증에서는 temp 0의 6개 prompt가 추측 디코딩 사용 전후 byte 단위로 같았고 약 127K·250K 문맥의 needle retrieval도 각각 3/3이었다. 제한된 검사이지 모든 생성 분포·모델 전체 1M 문맥 검증은 아니다. 공개 endpoint의 TTFT 약 198 ms는 네트워크 왕복을 포함해 내부 약 40 ms와 직접 혼동하지 않는다.

그래서: agent에게 단일 변수 변경·앞뒤 대조·실패 기록·배포 전 검증을 요구하는 최적화 절차를 참고할 수 있다. 속도 수치는 재현 조건과 함께 읽고 Claude·Codex의 모델 우열로 변환하지 않는다.

## IBM CUGA 인도 언어 음성 agent 사례 — 영어 문서를 다국어 검색으로 연결

- 분류: `음성`
- 출처: https://huggingface.co/blog/ibm-research/an-indic-voice-agent-with-cuga

IBM Research 팀은 11-25 CUGA 기반 Indic Voice Agent의 농업 도우미 사례와 튜토리얼·데모를 공개했다. CUGA 자체의 신규 출시나 새 음성 모델 발표가 아니다. 음성 질문을 텍스트로 바꾸고 영어 농업 안내서 154쪽을 검색한 뒤 질문 언어의 짧은 음성 답변과 출처 쪽수를 제공하도록 구성했다.
CUGA는 텍스트 입출력·모델 연결·도구·상태·guardrail을 맡고 ASR·TTS는 바깥 계층으로 분리한다. Sarvam AI cloud API를 브라우저에서 호출하거나 자체 서버의 SraVaani ASR·Svara TTS를 사용할 수 있다. CUGA agent 코드는 Apache 2.0이지만 별도 음성 서비스·모델의 조건까지 같은 라이선스로 보장하는 것은 아니다. 저장소: https://github.com/cuga-project/cuga-agent
영어 전용 기본 embedding이 힌디어·타밀어 질문에서 잘못된 문단을 찾아도 오류 없이 자료가 없다는 답변을 내던 문제를 설명했다. intfloat/multilingual-e5-large로 바꿔 교차 언어 검색을 처리하며 prompt 조정 전에 비영어 질문의 실제 검색 쪽수를 확인하라고 권한다.
음성에 불필요한 Markdown·인용 태그를 정리하고 단순 입력 검사와 OFF_TOPIC 신호로 별도 LLM guardrail 호출을 줄인다. 질문마다 새 thread를 사용하며 검색 문단에 근거하도록 지시한다. 이는 개발팀의 구현 사례로, 환각 0건·격리의 형식적 보장·독립 다국어 benchmark·측정된 end-to-end 지연 개선을 입증한 것은 아니다.

그래서: 다국어 음성 도우미에서는 ASR·TTS뿐 아니라 검색 embedding의 언어 적합성이 중요하다. 언어·도메인을 바꿀 때도 출처 검색부터 검증하는 재사용 가능한 agent 구성 사례다.
