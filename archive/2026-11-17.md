공급사 발표가 인용한 FrontierCode 2.0에서는 두 모델 모두 max일 때 Sol이 Astra보다 0.5점 이내 낮고 작업당 비용은 약 1/5이었다. Agents’ Last Exam에서는 Astra가 Fable 5.2보다 5.5점 높고 비용은 5%라고 설명했지만 Fable의 fallback 사용 9개 과제는 제외됐다. Terminal-Bench-Science의 Fable 결과는 mini-swe-agent이며 Anthropic의 Claude Code max 결과 74.6%와 다르므로 섞어 순위를 만들지 않는다.

## Claude Linked billing 베타 — 앱 사용자의 API 조직으로 요청별 비용 청구

- 분류: `도구`
- 출처: https://platform.claude.com/docs/en/manage-claude/oauth-apps/organization-billing-connections

Anthropic은 공식 API 변경 이력 11-17 항목에서 Linked billing 베타를 발표했다. OAuth로 고객의 Claude Platform 조직을 앱에 연결하고 user-profiles-billing-2026-10-01 베타 헤더와 요청별 billing_policy로 고객 또는 개발자 청구를 선택한다. 발표일 근거: https://platform.claude.com/docs/en/release-notes/overview
고객 조직은 API 사용료를 Anthropic에 직접 결제해야 한다. 선불 크레딧·청구서 결제는 가능하지만 AWS·Google Cloud·Azure 마켓플레이스 결제 조직과 Claude 구독 플랜만 있는 조직은 대상이 아니다. 고객은 앱별 지출 상한을 설정하거나 연결을 해제할 수 있다.
/v1/messages·/v1/chat/completions가 지원된다. 고객 청구 요청에서 유료 code execution은 지원하지 않고 Message Batches도 고객 청구를 지원하지 않는다. 고객에게 청구할 수 없는 요청을 개발자에게 자동 전가하지 않고 거절한다.
요청은 개발자 조직에서 실행되므로 개발자의 rate limit·모델 접근·서비스 계층·데이터 보존·암호화 키가 적용된다. 고객 조직의 ZDR·BAA·CMEK가 자동 승계되지 않으며, 베타라 엔드포인트·매개변수·동작이 바뀔 수 있다.

그래서: 고객의 API 예산을 에이전트 앱에 연결할 청구 경로가 생겼다. 개인 Claude 구독을 임의 앱에서 무제한 쓰는 기능으로 해석하지 말고 청구 자격과 데이터 처리 조건을 별도로 확인해야 한다.

같은 날짜에 Google Pay 결제 흐름도 설명했다. 상품·최대 가격을 설정하면 체크아웃을 준비하고 항목별 요약을 보낸 뒤 명시적인 1탭·기기 승인을 받아 결제를 진행한다. 이 기능은 미국의 18세 이상 개인 Google 계정 대상으로 영어·웹/Android/iOS에 순차 제공되며 한국의 Tasks 무료 확대와 제공 범위가 다르다.
문자 요청·진행 중 답장으로 작업 방향 변경, 이메일 전달로 Tasks 시작도 추가했다. 문자 기능은 미국 전화번호·지원 통신사·본인 확인이 필요하고 이메일 기능도 미국 18세 이상 개인 계정·영어 대상이다. 다른 나라에 동일한 입출력 채널이 열린다고 추정하지 않는다.
업체에 전화해 재고·견적을 확인하는 기능은 전화 계획 검토·승인, AI 신분 고지와 업체 수신 거부를 설명한다. 이번 원문은 제품 기능·제공 범위 안내이며 완료율·실행 속도·모델 벤치마크를 독립 측정한 자료가 아니다.

그래서: 한국 사용자에게도 반복 조사·브리핑을 맡길 무료 에이전트 접근 경로가 확대된다. 다만 결제·문자·이메일·미국 업체 전화 기능까지 한국에 일괄 제공되는 것으로 읽지 않아야 한다.
