background=true와 background_options.completion_window의 2h 또는 8h를 지정하고 Standard 처리(service_tier=default)를 사용한다. auto는 실제 Standard를 선택했을 때만 대상이다. stream은 생략하거나 false여야 하며 기본 soonest 창에는 이 할인이 없다. 전체 agent의 도구·인프라 비용이 30%·40% 줄어든다는 뜻은 아니다.
완료 목표는 API가 최초 요청을 접수한 때부터 그 응답에 적용한다. 여러 turn의 도구 실행·전체 workflow가 2·8시간 안에 끝난다는 보장은 아니다. 같은 project·model·창·continuation ID 등을 재사용하는 후속 요청은 높은 대기열 우선순위 자격을 얻지만 시작 시각은 스케줄링에 달린다. 적격 후속 요청에도 token 할인을 적용한다.
2h·8h 요청은 Batch와 Batch/Background Rate Limit을 공유하며 제출 때 입력 token을 계산한다. 할인 창에서 생성한 prompt cache는 일반 Standard 요청에서 재사용할 수 없다. GPT-6.2부터 새 모델은 Flex를 제공하지 않으며 기존 지원 모델의 Flex가 베타 종료 전까지 유지되는 것과 이번 공개 베타를 구분한다.

그래서: 즉시 답변이 필요 없는 분석·문서 검토에는 모델 token 단가와 완료 목표를 함께 선택할 수 있다. 기존 Flex나 실시간 agent 속도 개선으로 오해하지 않고 대기·turn·cache·한도 조건을 비용 비교에 반영한다.
